# 巡栈 / XunStack

服务器与应用安全检测与处置工具。正式路线为 Rust 本机服务、React / TypeScript 浏览器界面和 SQLite。

> 当前开发分支只导入了已有 Alpha 的 `xunstack-core` 检测核心，整套应用仍在接入中。核心测试通过不代表可以部署，也不代表回收站、漏洞引擎、终端和 UI 已验收。当前没有 Mac 应用安装包。

## 本次可检查的实现

- 风险、证据、文件身份和扫描覆盖的数据模型。
- 文件与少量静态配置规则；Laravel、Spring Boot / Cloud、BladeX 的识别线索。
- 基于原始路径身份和完整哈希的基线比较；未覆盖路径不能直接报告为删除。
- 本地公告的精确版本匹配。没有生产漏洞库，不是完整漏洞扫描器。
- 保护文件策略、展示转义和 CSV 公式注入防护。

本次尚未导入 HTTP 服务、真实目录扫描、数据库、正式前端和原型，也没有真实文件写入口。此前源码包不因这份提交而自动成为已验收产品。

## 检查

安装 `rust-toolchain.toml` 指定的工具链后，在仓库根目录运行：

```sh
cargo generate-lockfile
cargo check --workspace --all-targets --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

初次 CI 可以解析依赖生成真实锁文件以便审核；不是伪造锁文件。锁文件核验并提交后使用固定锁构建。该阶段 CI 只测试检测核心，分别在 Linux x86_64、macOS ARM64 和 macOS Intel 原生运行，不生成应用发行包。

## 后续接入与安全边界

沿用已有 Alpha 源码与高级原型，不重建普通后台模板。完成服务、认证、前端、真实只读扫描和报告，再独立验证回收站写层。代码、测试及实际运行结果为实现事实来源，不以目录存在或绿色核心检查宣称产品完成。

普通删除必须先进入回收站；永久删除每次由后端重新验密，只授权固定对象集合。恢复不得覆盖已有文件。未验证的文件写能力默认关闭，所有写测试只能使用自建临时目录。

AI 只在原型体现；完整 Shell 和主动漏洞探测权限未确认，不自行开放。没有真实公告库或完整检测证据时显示未覆盖，不把文件启发式冒充 CVE。

单管理员账号、密码和入口分别随机生成；不向仓库提交任何秘密、客户样本或生产数据库。目标为 Mac 与信创 Linux 的离线运行，但尚未完成应用构建和平台适配。

## 维护

只维护 `README.md` 和 `AGENTS.md` 两份手写说明。原型导入后放 `design/preview.html`，只供视觉和交互参考，不要求随代码同步。测试结果来自 CI，不新增 PRD / STATUS / SECURITY 等重复文档。

当前没有选择项目开源许可证；仓库公开可见不等于已经授予开源许可。保留 `publish=false`，不自动合并、部署、发布或修改仓库可见性。第三方许可与自动生成的测试材料不属于需要删除的说明文档。
